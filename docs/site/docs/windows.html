crabshell Docs

Windows

Crabshell has three kinds of window. Panels belong to a monitor, floating windows are ordinary application windows, and popups hang off a widget.

Panels

A PanelWindow is a layer-shell surface on one monitor. Bars, docks, launchers, notification stacks and wallpapers are all panels with different anchors and layers. 

PanelWindow::new(output)
  .anchors(Edge::Top | Edge::Left | Edge::Right)
  .height(30)
  .style(BAR)
  .child(Row::new())

Every method takes a value or a closure, unless the table says it takes a signal.

Method What it sets
anchors(edges) The edges the window sticks to, joined with |. With none, the compositor centers it. Two opposite edges stretch it between them.
width(px), height(px) The size in logical pixels. 0, the default, lets the compositor choose, as it does along an axis anchored on both sides.
exclusive_zone(px) The space other windows keep clear along the anchored edge. It defaults to a bar's height or width. 0 reserves nothing, and -1 covers other panels.
layer(layer) Layer::Background, Bottom, Top, the default, or Overlay.
margins(margins) Space from the anchored edges: Margins::all(8) or Margins::new(top, right, bottom, left).
keyboard_focus(focus) KeyboardFocus::None, the default, Exclusive or OnDemand. See keyboard focus.
namespace(name) The name compositor rules match on. It defaults to crabshell and is read once.
mask(region) The part that takes pointer input. See input masks.
blur(region) The part the compositor blurs behind. See blur.
on_key(handler) Keys nothing inside the window used. See keys.
style(style) The background, and the color and font its text inherits.
child(widget) The one widget that fills the window.
You want Anchors and size
A bar across the top Edge::Top | Edge::Left | Edge::Right, a height
A dock in the middle of the bottom edge Edge::Bottom, a width and a height
A panel in the top right corner Edge::Top | Edge::Right, a width, a height and margins
A launcher in the middle of the screen No anchors, a width and a height, Layer::Overlay
A wallpaper or a full-screen overlay All four edges

One function, every monitor

cx.per_output(f) calls f for every monitor that exists now or appears later. When a monitor goes, its windows go with it, along with everything f made. f returns a PanelWindow, or a Vec<PanelWindow> for several windows or none. 

crabshell::run(|cx| {
  cx.per_output(|cx, output| vec![bar(cx, output), toasts(cx, output)]);
});

output.name() is the compositor's name for the monitor, such as DP-1. 

cx.per_output(|cx, output| {
  if output.name() == "eDP-1" { vec![bar(cx, output)] } else { vec![] }
});

Call per_output from the root closure or from inside another per_output function. Called from a plain effect, it adds another set of windows on every run.

If f panics for one monitor, the log says so and that monitor gets nothing until it is plugged in again. The others carry on.

The monitors as a signal

cx.outputs() is a ReadSignal<Vec<OutputInfo>> of every monitor, kept current. Each has name, description, make, model, the mode with its width, height and refresh_mhz, the whole scale, the fractional_scale windows draw at, the logical x, y, width and height, width_mm, height_mm and transform. 

let outputs = cx.outputs();
let name = output.name();
// A wallpaper sized to its monitor.
let size = cx.memo(move || {
  outputs.with(|all| {
    all.iter().find(|info| info.name == name).map(|info| (info.width, info.height))
  })
});

Floating windows

A FloatingWindow is a window like any application's, placed and decorated by the compositor. Show one with cx.floating. 

let about = cx.signal(false);
cx.floating(
  FloatingWindow::new()
    .title("About")
    .width(320)
    .height(120)
    .visible(move || about.get())
    .on_close(move |_| about.set(false))
    .style(BOX)
    .child(Text::new("a shell written in Rust")),
);
Method What it sets
title(text) The title the compositor shows.
width(px), height(px) The size it asks for.
min_size((w, h)), max_size((w, h)) The limits of a resize. 0 leaves a side free.
maximized(bool), fullscreen(bool) Whether it asks to fill the screen.
visible(bool) Whether it is shown. Hidden, it has no surface.
on_close(handler) Runs when the user or the compositor asks it to close.
style, child, mask, blur As on a panel.

The window lives as long as the context cx.floating was called on, so keep it for the session and bind visible.

A widget inside can let the user move or resize the window. These work only while a pointer button is held, so call them from a button's on_press. 

Button::new(Text::new("drag me")).on_press(|cx| cx.start_move())

cx.start_resize(Edge::Bottom | Edge::Right) resizes from a corner, and cx.minimize() minimizes.

Popups

A PopupWindow opens next to the widget that asked for it and is as large as its content. Open one from an event handler. 

Button::new(Text::new("power")).on_click(|cx| {
  cx.open_popup(|_cx| {
    PopupWindow::new().style(MENU).child(
      Column::new()
        .child(Button::new(Text::new("Lock")).on_click(|cx| {
          cx.exec_detached(["loginctl", "lock-session"]);
          cx.close_popup();
        }))
        .child(Button::new(Text::new("Suspend")).on_click(|cx| {
          cx.exec_detached(["systemctl", "suspend"]);
          cx.close_popup();
        })),
    )
  })
})

The popup closes when its widget goes, on a click outside, or on cx.close_popup(). By default it opens below its widget from a horizontal bar and beside it from a vertical one, and flips or slides to stay on the monitor. Three methods change that, each read when it opens.

Method What it sets
edges(edges) The edge or corner of the widget the popup hangs from.
gravity(edges) Which way it extends from there.
adjustment(adjust) How it may move to stay on the monitor: Adjust::FLIP, SLIDE, RESIZE, ALL or NONE, or one axis with FLIP_X, FLIP_Y, SLIDE_X, SLIDE_Y, RESIZE_X and RESIZE_Y, joined with |. The default flips and slides.

A popup also takes style, child and mask.

Menus

Menu is a ready-made list of entries for a popup, with separators, checkmarks, radio marks and submenus. The tray uses it, and you can build your own from MenuEntry values. 

fn entry(id: i32, label: &str) -> MenuEntry {
  MenuEntry {
    id,
    label: label.to_string(),
    separator: false,
    enabled: true,
    toggle: None,
    checked: false,
    submenu: false,
    children: Vec::new(),
  }
}

Button::new(Text::new("sound")).on_right_click(|cx| {
  let entries = vec![
    entry(1, "Mute"),
    MenuEntry { separator: true, ..entry(0, "") },
    entry(2, "Sound settings"),
  ];
  cx.open_popup(move |_cx| {
    PopupWindow::new().child(Menu::new(entries).on_activate(|cx, id| {
      if id == 1 {
        cx.audio().toggle_mute();
      }
      cx.close_popup();
    }))
  });
})

A MenuEntry is a plain struct with id, label, separator, enabled, a toggle of MenuToggle::Checkmark or Radio with checked, and submenu with children. Menu takes style, item_style, hover_style and separator_style, plus on_activate and on_open_submenu handlers that get the entry's id.

Keyboard focus

A window gets keys only if it asks for the keyboard.

Value When the window has the keyboard
KeyboardFocus::None Never. The default, and right for a bar.
KeyboardFocus::Exclusive Always, while it is in the top or overlay layer. Right for a launcher.
KeyboardFocus::OnDemand When the user clicks it. It needs layer-shell version 4.

Floating windows take the keyboard as any application window does.

  • inhibit_shortcuts(bool) asks the compositor to send its own shortcuts to the window while it has the keyboard. shortcuts_inhibited(signal) reports whether it agreed.
  • focus_grab(signal) takes a Signal<bool>. While it is true, the windows given that signal hold the keyboard and pointer, and a click elsewhere writes false. This is how a menu closes when you click away. It needs Hyprland.

Input masks

mask sets which part of a window takes pointer input. Clicks outside it reach whatever is below. None, the default, is the whole window, and Region::empty() lets every click through. 

Region::rect(0, 0, 340, 64)               // x, y, width, height
Region::rect(0, 0, 340, 64).radius(8.0)   // rounded corners
Region::ellipse(0, 0, 48, 48)
Region::rect(0, 0, 400, 300).subtract(Region::rect(100, 100, 200, 100))

union, subtract, intersect and xor combine regions. A window larger than what it shows, such as a notification stack, masks itself to its content. 

.mask(move || {
  let tall = (popups.with(Vec::len) as u32 * 64).min(400);
  Some(Region::rect(0, 0, 340, tall))
})

Blur and opacity

blur(region) asks the compositor to blur what is behind that part of the window. Give the window a translucent background. 

PanelWindow::new(output)
  .height(48)
  .blur(Some(Region::rect(0, 0, u32::MAX, 48)))
  .style(Style::new().background(Color::rgba(0x1e, 0x1e, 0x2e, 0xd8)))

It needs ext-background-effect-v1. Without it the window shows unblurred.

Two more hints exist for Hyprland. compositor_opacity(0.0..=1.0) fades the whole window, blur included, where a style's opacity fades only what Crabshell paints. visible_mask(region) names the part of the window that holds anything to see.

Keeping the screen awake

inhibit_idle(bool) on a panel or a floating window keeps the screen from blanking while it is true and the window shows. To learn when the user is away, see idle time. 

let awake = cx.signal(false);
PanelWindow::new(output).inhibit_idle(move || awake.get())

Screen readers

When a screen reader such as Orca is on, the shell tells it about every window and widget: buttons by their text, fields by their placeholder, and Enter-like clicks through it. Give a button that shows only an icon a name: 

Button::new(Icon::new("audio-volume-high-symbolic"))
  .accessible_name("Volume")

With no screen reader on, the shell holds no accessibility connection. NO_AT_BRIDGE=1 turns it off entirely.

Showing and hiding

Way While hidden
Keep the window, with transparent content and mask set to Region::empty() The surface stays. Right for something that animates in and out.
Return an empty Vec from per_output No window, decided when the monitor appears.
Build it in a child context and dispose the context No window, bindings, timers or programs. Right for a launcher or a dashboard.

A floating window has visible. A session lock has rules of its own.
