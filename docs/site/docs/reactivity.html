crabshell Docs

Signals and effects

State lives in signals. A closure that reads a signal runs again when it changes, and only what that closure feeds repaints.

Signals

let count = cx.signal(0_u32);

count.get();                 // a copy of the value
count.with(|n| *n > 3);      // read by reference, without cloning
count.set(5);                // replace it
count.update(|n| *n += 1);   // change it in place

A signal is a small Copy handle, so it moves into any number of closures with no clone(). get() clones the value. For a long list, read by reference with with. 

let count = workspaces.with(|all| all.len());

A ReadSignal<T> is the same handle without set and update. Services hand these out, and signal.read_only() makes one from your own.

Bindings

Every widget property takes a value or a closure.

Text::new("volume")                              // set once
Text::new(move || format!("{}%", volume.get()))  // a binding

A binding runs when the widget is built and again whenever a signal it read changes. What it reads is recorded on every run, so a branch that stops reading a signal stops depending on it. 

Text::new(move || {
  if expanded.get() {
    title.get()      // read only while expanded
  } else {
    String::new()
  }
})

Each property is its own binding. A changed color repaints one widget. A changed size or text lays the window out again and repaints what moved.

A property the widget itself writes, such as a TextInput's text, takes a Signal instead.

Memos

let shown = cx.memo(move || {
  let query = query.get().to_lowercase();
  apps.iter().filter(|app| app.contains(&query)).cloned().collect::<Vec<_>>()
});

A memo derives a value and is read like a signal. It recomputes only when read after an input changed, and if the new value equals the old one, nothing that reads it runs. Its type needs PartialEq.

A signal notifies on every set, even with the value it already holds. Reading it through a memo filters those out. 

let open = cx.signal(false);
let is_open = cx.memo(move || open.get());
// An effect that reads is_open runs only when the value really flips.

A memo must not write signals.

Effects

cx.effect runs code now, and again whenever a signal it read changes. 

// A new search starts at the top of what it finds.
cx.effect(move || {
  shown.get();
  picked.set(0);
});
  • set and update never run anything on the spot. Marked effects run together before the next layout, so five writes in one handler repaint once.
  • Each effect runs at most once per round, in the order the effects were made.
  • An effect that keeps writing a signal it reads is stopped after 100 rounds and logged.

get_untracked() and with_untracked() read without subscribing, and untrack(|| ...) does the same for a whole block. 

// Send the slider's value to the sink. Only the slider should run this.
let parent = cx.clone();
cx.effect(move || {
  let percent = value.get().round() as u32;
  let name = sink.with_untracked(|sink| sink.as_ref().map(|sink| sink.name.clone()));
  if let Some(name) = name {
    parent.audio().set_sink_volume(&name, percent);
  }
});

Lists

Column::new().children_keyed(
  move || notifications.get(),                 // the items
  |notification: &Notification| notification.id, // a key for each
  |cx, notification| {                          // the child for one key
    Text::new(move || notification.get().summary)
  },
)

children_keyed builds one child per item of a changing list. The first closure gives the items, the second a key for each, and the third builds the child for a key. That child is kept while its key stays in the list. It gets a context of its own and a Memo<T> holding its item. When the key leaves, the child and everything made in its context are freed. Items need Clone and PartialEq, and a duplicate key is logged and skipped.

.exit(duration) and .displaced(transition) animate children that leave or move. See Timers and motion. For long lists, ListView and GridView build only the rows in view.

Contexts

Everything made with a Cx belongs to it: signals, effects, timers, running programs, windows. When the context goes, all of it is freed.

Where Its context lives until
The closure given to crabshell::run The shell exits
The function given to cx.per_output That monitor is unplugged
The third closure of children_keyed That key leaves the list
An event handler such as on_click Its widget goes
cx.child() You dispose it

So a signal made inside per_output's function is one per monitor, and one made in the root closure is shared.

cx.child() makes a context you control, which is how to show something that costs nothing while hidden. Here a panel exists only while open is true. 

let shown: Rc<RefCell<Option<Cx>>> = Rc::default();
let parent = cx.clone();
cx.effect(move || {
  if let Some(old) = shown.borrow_mut().take() {
    old.owner().dispose();
  }
  if open.get() {
    let child = parent.child();
    untrack(|| child.per_output(move |cx, output| panel(cx, output)));
    *shown.borrow_mut() = Some(child);
  }
});

untrack keeps the effect from subscribing to what the panel reads. per_output is called on the child, so its windows go when the child does.

Reading a signal whose context is gone panics, and the panic is logged and contained. try_get() returns None instead, and try_set() returns false.

One value for the whole shell

cx.provide(value) makes one value of a type reachable from every context, and cx.service::<T>() fetches it. Use it for something the whole shell reads, such as a theme. 

struct Theme {
  accent: Signal<Color>,
}

crabshell::run(|cx| {
  let accent = cx.signal(Color::hex("#89b4fa"));
  cx.provide(Theme { accent });
  cx.per_output(bar);
});

fn dot(cx: &Cx) -> Row {
  let theme = cx.service::<Theme>().expect("the root closure provides the theme");
  let accent = theme.accent;
  Row::new().style(move || DOT.background(accent.get()))
}

Widgets of your own

A function that returns a widget is a component. To let an argument take a value or a closure, accept impl IntoProp<T>. 

fn chip(label: impl IntoProp<String>, on: impl IntoProp<bool>) -> Button {
  let on = on.into_prop().shared();
  Button::new(Text::new(label)).style(move || if on() { CHIP_ON } else { CHIP })
}

chip("Wi-Fi", true);
chip("Bluetooth", move || bluetooth_on.get());

It passes straight to a widget method of the same type. To read it in your own closure, into_prop().shared() turns it into a function you can call.

When a closure panics

Every closure you give the toolkit runs inside catch_unwind. A panic is logged with where it is, and that one closure is disabled. 

PanelWindow[DP-1]/Row/Button[2]/Text.text panicked and is disabled: index out of bounds: the len is 2 but the index is 5

The path reads from the window down. Button[2] is the row's third child and .text the property. The text keeps its last value, and the rest of the shell keeps running.

Two panics are not contained. One in the root closure exits with status 1. One inside the toolkit's own drawing or Wayland code ends the process, and crabshell run restarts it.
