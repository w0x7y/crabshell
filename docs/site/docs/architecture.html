crabshell Docs

How it works

You can write a shell without reading this page. It explains why Crabshell is fast, why it sleeps, and where a change to Crabshell itself would go.

Two processes

+---------------------------------+               +---------------------------------+
| Config crate                    |    on save    | crabshell run, the supervisor   |
| ~/.config/crabshell/src/main.rs | ------------> | watches src/, runs cargo build  |
| plain Rust and typed styles     |               | restarts on crash, keeps        |
+---------------------------------+               | last-good                       |
                |                                 +---------------------------------+
                | compiled into the binary                        |
                v                                                 | starts it
+---------------------------------------------------------------------------------+
| The shell, your own program                                     v               |
|                                                                                 |
|   config code ----> signals <---- services                                      |
|                        |          Sway, tray, audio, clock, ...                 |
|                        v                                                        |
|                     widgets and layout                                          |
|                        |                                                        |
|                        v                                                        |
|                     drawing, on the CPU, of what changed                        |
|                        |                                                        |
|                        v                                                        |
|                     Wayland: windows, buffers, input                            |
+---------------------------------------------------------------------------------+
                         |  buffers out, input events in
                         v
                    the compositor

The supervisor only builds the config and swaps the running shell. The shell is a normal program that links the crabshell library, so a crash in your config can't take the supervisor down, and the supervisor can always start the last build that worked.

A reload starts the new shell beside the old one, and the old one exits once the new one is ready, so the bar never leaves the screen. Until then the new bar reserves no space of its own, so windows stay where they are until the old bar goes.

One thread, one loop

Everything in the shell runs on one thread. Each turn of the event loop does five things.

  1. Dispatch every source that is ready: Wayland events, timers, D-Bus, the compositor's IPC socket, the audio channel.
  2. Run the effects those events queued.
  3. Lay out every window marked for layout.
  4. Draw each window that is dirty and whose frame callback has arrived.
  5. Flush the Wayland connection and sleep until a source is ready.

When nothing is dirty there is no layout, drawing or commit, so idle costs nothing. A wakeup has to come from outside: the compositor, a bus, or a timer you started.

One thread also means no locks and no Arc. A few jobs run on helper threads: the audio library, the D-Bus library's socket, each PAM attempt and color quantizing. Each hands its results back to the loop as messages.

The reactive core

Signals, memos and effects live in one table per thread, and a handle is a small Copy key into it. Each node belongs to an owner, and disposing an owner frees every node made under it.

  • Reading a signal inside a memo or an effect records a dependency, again on every run.
  • Writing a signal marks what depends on it and queues effects. It never runs them on the spot.
  • The loop runs the queue once per turn, before layout. Each effect runs at most once per round.
  • A memo recomputes only when read while stale, and tells its readers only if its value changed.

Every binding is an effect that writes one property of one widget. There is no tree diff, since a change already knows which property it lands on.

Widgets, layout and damage

A widget is a description. When a window is built, each one becomes a node with its own owner, and each property given a closure becomes an effect.

Kind Examples What a change costs
Paint Colors, backgrounds, gradients, borders, opacity, radius, masks, transforms The widget's own area is marked dirty. Nothing is laid out.
Layout Text, fonts, padding, gaps, sizes, children The window is laid out again, and every widget that moved is marked dirty at its old and new place.

Layout is flexbox and grid, computed by taffy. Text is measured with the same buffer it is drawn from.

Drawing

Crabshell draws on the CPU with tiny-skia, into shared-memory buffers the compositor reads. A 1920 by 30 bar's buffer is 225 KiB.

  • Each frame repaints only the widgets that cross a dirty rectangle, and tells the compositor which pixels changed. When more than half a window is dirty, the whole window repaints.
  • A window cycles through two or three buffers. Each remembers which frames it missed and repaints those areas before it is used again.
  • After a commit the shell asks for a frame callback, and draws again only when it arrives and something is dirty.
  • A buffer is the logical size times the monitor's scale. Scales of 1, 1.25, 1.5, 1.75 and 2 are each tested against reference pictures.

Text is shaped by cosmic-text. The shell asks fontconfig for the families your styles name and loads only those files.

A frame of the effects example, with a sliding indicator and a fading hover on a 1920-pixel bar, takes 0.31 ms to draw at scale 1 and 0.54 ms at scale 2, under 4% of a frame at 60 Hz.

Outside data is not trusted

Icons, images, theme files, tray pixmaps, D-Bus replies, IPC messages and compositor events come from other programs. Each has a size limit, and malformed or oversized input is logged and skipped. An SVG can't load outside files, a picture's size is checked before memory is allocated, and an IPC request is capped at 64 KiB.

Panics

The toolkit wraps every call into your code in catch_unwind: bindings, effects, event handlers, per_output functions, list builders, paint closures, timer callbacks and IPC handlers. The reactive core releases every internal borrow before it calls you, so a caught panic never leaves it broken.

A panic in the toolkit's own drawing or Wayland code is not caught. The process exits, and the supervisor restarts it.

The four rules

Every change to Crabshell is checked against four rules, and a broken rule blocks it.

Rule What it means How it is checked
Stay light Idle memory at or under 30 MB on one 1080p monitor. First frame within 100 ms. A measured run of the counter bar on the change and on the commit before it.
Idle means asleep Nothing dirty means no commit and no wakeup. A clock ticking once a minute is the only periodic wakeup a bar gets. A test counts the idle bar's context switches over a minute. Each new source of wakeups gets its own idle test.
A config is plain Rust A normal Cargo crate that calls crabshell::run. Every property takes a value or a closure, signals are Copy, and Style is a constant. Each new public item is checked against those three points.
One bad binding never takes the shell down Your code runs inside catch_unwind, with a logged widget path. Each new place the toolkit calls your code gets a test that panics there and checks the log and that the shell keeps running.

The crates

Crate What it owns
crabshell run, per_output, the prelude, persisted state, IPC, and the examples. The one crate a config depends on.
crabshell-reactive Signals, memos, effects and owners.
crabshell-ui Cx, widgets, styles, layout, text, focus, pointer input and the animation clock.
crabshell-render Drawing, damage tracking, glyphs, icons and images.
crabshell-wayland The event loop, windows, buffers, scale, input and monitors.
crabshell-services Everything on the services, compositors, system and logins pages.
crabshell-cli The crabshell command and the config template.

Every crate forbids unsafe, and Wayland is spoken in pure Rust. Four system libraries are linked: fontconfig, libpulse, libxkbcommon and PAM. Dependencies must be MIT, Apache-2.0, BSD, ISC, Zlib or Unicode licensed, which CI checks on every push.
