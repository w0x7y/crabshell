crabshell Docs

When something breaks

Start with the log. crabshell run prints the compiler's errors, every panic with its place in the widget tree, and each thing the shell looked for and didn't find. 

$ CRABSHELL_LOG=debug crabshell run

It doesn't build

**The first build fails in a -sys crate or says a library wasn't found.** A system library's development files are missing. Install and run has the package names.

**crabshell run says it can't find cargo.** Cargo isn't on the PATH of the session that started it, which is common when a display manager starts the compositor. Set PATH where the session reads it, or set CARGO to cargo's full path.

A method doesn't exist, or takes other arguments. Check the crabshell = "0.6" line of your Cargo.toml. These pages describe 0.5, and a new minor version can change the API.

The borrow checker complains about a closure. Three habits fix most of it.

  • Write move on every closure you give the toolkit.
  • Signals, memos and timers are Copy. A String or a Vec isn't, so make a copy for each closure.
  • Service handles such as cx.hyprland(), and Cx itself, are cheap to clone(). 
let name = output.name();
let for_items = name.clone();
Row::new()
  .child(Text::new(name))
  .children_keyed(move || workspaces_on(&for_items), |w| w.id, row)

Nothing shows

The shell exits at once with status 2. It found no compositor, or the compositor has no layer-shell. Check that WAYLAND_DISPLAY is set where you ran it. GNOME's compositor doesn't offer layer-shell.

It runs, but there is no bar. Look for a panic from per_output in the log, which leaves that monitor empty until the next reload. Also check that the window has a size. A panel anchored to one edge needs both a width and a height.

Two bars are stacked. Another bar is still running. Stop it, or remove it from your compositor's config.

Windows sit under the bar. Set exclusive_zone to the bar's height. It is the default for a bar anchored across the top or bottom, so check the anchors.

The text is there but can't be seen. Text is black until a style gives it a color. Set one on the window's style.

Parts of it are empty

A service whose daemon isn't there gives an empty list or None, and says so once in the log.

No workspaces. cx.sway() needs SWAYSOCK, which only Sway sets. See which one to use.

"no audio". No PulseAudio or pipewire-pulse answered. The service retries for a minute after startup, so if the audio server started later, restart the shell.

No tray icons. The tray needs a D-Bus session bus. Some applications show an icon only when asked, as with nm-applet --indicator.

No notifications. Another notification daemon holds the name. Stop it, and the shell takes over.

An icon is missing. The shell uses GTK's icon theme, and without one hicolor, which has only what applications install. Call cx.set_icon_theme with a full theme such as "Adwaita". For a file, pass a Path, since a &str is always a name.

The wrong font shows. The family you named isn't installed, and fontconfig picked its closest match. fc-match "Inter" shows what a name resolves to.

A widget stopped updating

Its binding panicked. Find a line like this in the log. 

PanelWindow[DP-1]/Row/Button[2]/Text.text panicked and is disabled: called `Option::unwrap()` on a `None` value

The path reads from the window down. Button[2] is the row's third child, and .text is the property. That one binding is off and keeps its last value. Fix the closure and save. Handlers are named the same way, as handler <path>.on_click.

The usual cause is an unwrap() or an index on data from outside. A list can be empty for a moment while a service connects, so write the empty case.

It never updated at all. The closure isn't reading a signal. 

let name = ws.get().name;          // read once, outside any closure
Text::new(name)                    // so this never changes

Text::new(move || ws.get().name)   // read inside the closure: follows the signal

get_untracked() and anything inside untrack(...) read without subscribing, on purpose.

Something runs too often

An effect runs when nothing changed. A signal notifies on every set, even with an equal value. Read it through a memo, which passes on only real changes. 

let is_open = cx.memo(move || open.get());
cx.effect(move || if is_open.get() { build() });

Windows multiply. cx.per_output was called inside an effect, so each run added another set. Call it from the root closure, or on a child context the effect disposes first.

The log says an effect ran 100 rounds. It writes a signal it also reads, and the shell disabled it. Read with get_untracked() the signals it should not react to.

A signal "has no value" or its context is gone. A closure outlived the context its signal was made in. Make the signal in the longer-lived context, or use try_get().

Input goes to the wrong place

Keys don't reach the window. A panel takes no keyboard by default. Set keyboard_focus(KeyboardFocus::Exclusive) for a launcher, or OnDemand for a window the user clicks into.

Clicks don't reach what is behind an empty part of a window. The whole window takes input unless you set a mask.

A click on a list row does nothing. Only a Button hears the pointer. Wrap the row in one.

Reloads

Saving doesn't reload. crabshell run watches only Cargo.toml and src/ in the config directory. A save that changes nothing isn't swapped in.

The shell went back to an older version. The new build crashed three times in a minute, so crabshell run started the last build that worked. The crash is in the log, and your next save tries again.

State resets on every save. Only cx.persist values survive a reload.

The screen is locked and the shell is gone. Start the shell again. If your config remembers that it was locked, it takes the lock back and can unlock. Otherwise switch to another virtual terminal and start a lock program such as swaylock there, with WAYLAND_DISPLAY set to the session's. It takes the lock over, and you unlock with it.

Is my shell asleep?

A shell that wakes when nothing changes wastes battery. Count how often yours returns from waiting over five idle minutes. 

$ perf stat -e 'syscalls:sys_exit_epoll_wait' -p $(pgrep -n my-shell) -- sleep 300

A bar with a minute clock should show a handful, all on the minute. Common sources of more:

  • A clock with Precision::Second.
  • A cx.interval that runs while what it feeds isn't on screen.
  • An audio level meter from peaks.
  • A cx.cycle or cx.frames whose running never turns false.
  • A live ScreencopyView of something that keeps changing.

For memory, ps -o rss= -p $(pgrep -n my-shell) prints the resident size in KiB. The template bar uses about 21 MiB.

Still stuck

Open an issue on GitHub with the output of CRABSHELL_LOG=debug crabshell run, your compositor and its version, and the smallest config that shows the problem.
