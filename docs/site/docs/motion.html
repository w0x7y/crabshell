crabshell Docs

Timers and motion

Motion runs on one clock that ticks only while something moves. When the last animation settles, the shell goes back to sleep.

Timers

let hide = cx.after(Duration::from_millis(1500), move || shown.set(false));
let poll = cx.interval(Duration::from_secs(1), move || samples.update(|all| all.push(read_cpu())));

cx.after runs a closure once and cx.interval runs one every period. Each returns a Timer, a Copy handle that goes with its context.

Method What it does
stop() Stops it before it fires again.
restart() Counts the delay or period again from now.
running() Whether it will fire. A binding that reads it follows it.
stopped() Gives the timer back stopped before it ever fires, so it waits for its first restart().

restart makes a debounce. This volume display shows while its timer runs, and each change starts the count again. 

// Waits for the first change.
let hide = cx.after(Duration::from_millis(1500), || {}).stopped();
cx.effect(move || {
  volume.get();
  hide.restart();
});
let shown = move || hide.running();

An interval is a wakeup, so run one only while what it feeds is on screen.

Transitions and curves

const SLIDE: Transition = Transition::new(250);
const POP: Transition = Transition::new(300).easing(Easing::OutBack);
const LATE: Transition = Transition::new(200).delay(100);
Method What it does
Transition::new(ms) A transition this many milliseconds long.
easing(easing) The curve. The default is Easing::OutCubic.
delay(ms) Waits before it moves.
alternate() Makes a cycle come back the way it went.

Style::transition_out(transition) sets how a button's style fades back to its own after a hover, pressed or focus style, so a hover can come in fast and leave slowly. Without it the fade back takes the style's transition. 

const TAB: Style = Style::new()
  .transition(Transition::new(80))
  .transition_out(Transition::new(400));

Easing has Linear, and In, Out and InOut forms of Quad, Cubic, Sine, Quart, Quint, Expo, Circ and Back, written as OutCubic. Bezier(x1, y1, x2, y2) is a CSS cubic-bezier, and Spline(&[[c1x, c1y, c2x, c2y, x, y], ...]) joins several segments.

Animated values

cx.animate(target, transition) returns a signal that follows a closure, moving to each new value instead of jumping. The value is an f32, a Point, a Color, or your own type that implements Animate. 

let picked = cx.signal(0_usize);
// Slides to the picked tab.
let x = cx.animate(move || picked.get() as f32 * 44.0, Transition::new(250));

Row::new().style(move || INDICATOR.translate(x.get(), 0.0))

cx.animation is the same with a handle that also says whether it is moving. 

let slide = cx.animation(move || if shown.get() { 1.0 } else { 0.0 }, POP);

slide.value();     // the ReadSignal<f32>, as cx.animate returns
slide.running();   // a ReadSignal<bool>, true from a new target until it settles

An effect on running() is where to put whatever follows an animation. Here a window takes no clicks once it has slid out. 

.mask(move || (!shown.get() && !slide.running().get()).then(Region::empty))

The transition of cx.animate and cx.animation takes a value or a closure, read as each new target starts, so one animation can take a different curve in and out. 

let y = cx.animate(
  move || if shown.get() { 0.0 } else { 60.0 },
  move || if shown.get() { POP } else { SLIDE },
);

Springs

cx.spring(target, spring) follows an f32 on a spring, which keeps its speed when the target moves. Spring::new(stiffness, damping) takes how hard it pulls and how fast it settles, and Spring::default() is 700 and 0.9, Material 3's standard spatial spring. A lower damping bounces more. 

let x = cx.spring(move || target.get(), Spring::new(700.0, 0.9));
x.value();     // the ReadSignal<f32>
x.running();   // true until the value rests

It gives an Animation<f32>, as cx.animation does. A 0.5 config that read the spring straight reads x.value() now.

Cycles

cx.cycle(running, transition) gives progress from 0 to 1 that repeats while running is true, for spinners and pulses. With alternate() it goes there and back. 

const SPIN: Transition = Transition::new(900).easing(Easing::Linear);
const PULSE: Transition = Transition::new(600).easing(Easing::InOutSine).alternate();

let turn = cx.cycle(move || busy.get(), SPIN);
Row::new().style(move || SPINNER.rotate(turn.get() * 360.0))

let glow = cx.cycle(move || recording.get(), PULSE);
Row::new().style(move || DOT.opacity(0.5 + glow.get() / 2.0))

Sequences

cx.sequence(initial, trigger, steps) plays keyframe steps one after another each time trigger's value changes, as Qt's SequentialAnimation does. A password pill shakes left, right and back each time a counter bumps. 

const SHAKE: [Step<f32>; 3] = [
  Step::to(-14.0, Transition::new(70).easing(Easing::OutQuad)),
  Step::to(12.0, Transition::new(90).easing(Easing::InOutQuad)),
  Step::to(0.0, Transition::new(95).easing(Easing::OutQuad)),
];

let wrong = cx.signal(0_u32); // bumped on each wrong password
let shake = cx.sequence(0.0, move || wrong.get(), SHAKE);
Row::new().style(move || PILL.translate(shake.value().get(), 0.0))

Step::to(value, transition) moves from wherever the value is, and Step::hold(ms) waits. A hold lets the shell sleep instead of drawing frames. The trigger's first value plays nothing, and a new one mid-play starts over from where the value is. It gives an Animation, so an effect on running() runs what comes after the last step, holds included, such as an unlock.

Looping sequences

cx.sequence_loop(initial, running, steps) repeats its steps while a closure says so, holds included. Loading tiles pulse one after another when each waits Step::hold(index * 140) first. When it stops, it finishes the round and rests on the last value, so nothing freezes mid-fade. 

const SINE: Transition = Transition::new(1100).easing(Easing::InOutSine);

let steps = [Step::hold(index * 140), Step::to(0.4, SINE), Step::to(1.0, SINE)];
let pulse = cx.sequence_loop(1.0, move || loading.get(), steps);
Row::new().style(move || TILE.opacity(pulse.value().get()))

Steps at the start of a sequence that take no time, Step::to(v, Transition::new(0)), land in the same flush that changes the trigger, before anything is drawn, so a jump-then-slide never shows the old value for a frame.

cx.sequence_now(initial, steps) has no trigger: it plays once, as soon as it is made. Use it for an entrance that plays each time a panel opens and builds its contents, with a hold per item for a stagger.

A value for each frame

cx.frames(running) gives the time since running turned true, updated on each frame. 

let time = cx.frames(move || shown.get());
// A dot that bobs up and down.
Row::new().style(move || DOT.translate(0.0, 4.0 * (time.get().as_secs_f32() * 6.0).sin()))

Children that leave and move

.exit(duration) after children_keyed keeps a removed child mounted at most that long, with cx.leaving() true inside it, so the child can animate itself out. It goes as soon as nothing made inside it moves, so the exit is a limit, not a length to match by hand. Motion stepped by cx.interval, a GIF, or an animation made outside the child doesn't hold it. Inside a nested list, cx.leaving() is also true while an item around it leaves. 

Column::new()
  .gap(8)
  .children_keyed(move || popups.get(), |n: &Notification| n.id, toast)
  .exit(Duration::from_millis(250))
fn toast(cx: &Cx, notification: Memo<Notification>) -> Button {
  let entered = cx.signal(false);
  let leaving = cx.leaving();
  let x = cx.animate(
    move || if entered.get() && !leaving.get() { 0.0 } else { 340.0 },
    Transition::new(250),
  );
  // Set after the animation took its first value, so the next round slides it in.
  entered.set(true);

  Button::new(Text::new(move || notification.get().summary))
    .style(move || TOAST.translate(x.get(), 0.0))
}

The toast starts off to the right, slides in because entered flips right after the animation is made, and slides back out while leaving is true. A leaving child still takes clicks.

.displaced(transition) slides the remaining children to their new places when one is added, removed or moved. 

Column::new()
  .children_keyed(items, key, row)
  .exit(Duration::from_millis(200))
  .displaced(Transition::new(200))

What motion costs

While an animation runs, the shell draws a frame each time the compositor asks, and repaints only what moves. A sliding indicator with a fading hover on a 1920-pixel bar takes 0.31 ms a frame at scale 1. Move things with translate, scale and rotate where you can, since animating a width lays the window out on every frame.
