crabshell Docs

Programs, files and IPC

The parts of a shell that reach outside the process: programs, files, saved state, sockets and commands from a terminal.

Run a program and read what it prints

cx.process runs a program and keeps what it prints and how it ended. 

let kernel = cx.process(|| ["uname", "-r"]).stdout();
Text::new(move || kernel.get().trim().to_owned())

The closure returns the command, a list such as ["uptime", "-p"] or a std::process::Command. It is a binding, so when a signal it read changes, the program is stopped and started again. 

// Runs again each time `host` changes.
let ping = cx.process(move || vec!["ping".to_string(), "-c1".to_string(), host.get()]);
Method What it gives or does
stdout(), stderr() Signals holding everything printed this run, up to 1 MiB.
running() A signal that is true until the program ends or fails to start.
exit_status() A signal holding how the last run ended, or None while it runs.
on_line(handler) Calls handler with each line as it comes.
on_split(marker, handler) The same, split at another marker such as "\0". An empty marker hands over each read as it arrives.
with_stdin(), write(data), close_stdin() Gives the program an input and feeds it.
kill() Sends SIGTERM.
restart() Stops it and starts the command again.
stopped() Starts nothing until the first restart(), for a program run on demand. Chain it on the call.

on_line, on_split and with_stdin are chained on the call, since they return the process. 

// Follow a program that prints one line per change.
let layout = cx.signal(String::new());
cx.process(|| ["my-keyboard-watcher"]).on_line(move |line| layout.set(line.to_owned()));

A program is stopped when its context goes, and the shell stops every program it started before it exits or reloads.

To poll something that has no events, start a program on a timer, in a context that lives only while the value shows. 

let uptime = cx.process(|| ["uptime", "-p"]);
let text = uptime.stdout();
cx.interval(Duration::from_secs(60), move || uptime.restart());

A program a button runs is one process, made stopped and restarted on each click. 

let screenshot = cx.process(|| ["grim", "-g", "0,0 1920x1080", "/tmp/shot.png"]).stopped();
Button::new(Text::new("shot")).on_click(move |_cx| screenshot.restart())

Start a program and let it go

cx.exec_detached(command) starts a program that runs by itself, as a launcher does. The shell doesn't read its output or wait for it, and it keeps running after a reload. 

Button::new(Text::new("Files")).on_click(|cx| cx.exec_detached(["nautilus"]))
Button::new(Text::new("docs")).on_click(|cx| cx.exec_detached(["xdg-open", "https://docs.rs/crabshell"]))

Installed applications

cx.desktop_entries() reads the .desktop files in the XDG data directories. 

let entries = cx.desktop_entries();
let apps = entries.applications();
let shown = cx.memo(move || {
  let query = query.get().to_lowercase();
  apps.with(|all| {
    all
      .iter()
      .filter(|entry| !entry.no_display && entry.name.to_lowercase().contains(&query))
      .cloned()
      .collect::<Vec<_>>()
  })
});
Method What it gives or does
applications() Vec<DesktopEntry>, sorted by name.
lookup(app_id) The entry a window's app id names, trying the exact id, then other spellings and the entry's StartupWMClass.
launch(id) Starts an application by its entry's id. A terminal application runs through xdg-terminal-exec.
launch_action(id, action) Starts one of its actions, such as a browser's "New private window".

A DesktopEntry has id, name, generic_name, comment, icon, exec, terminal, categories, keywords, no_display, dbus_activatable, startup_wm_class, working_dir, command, actions and the file's path. Entries marked no_display are in the list, so filter them out of a launcher. The directories are watched, links on the way included, so a newly installed application shows up without a restart, and so does a NixOS profile swapped behind a link.

An entry with DBusActivatable=true is started over D-Bus, as the spec asks, and its Exec runs only when the app isn't on the bus. An Exec line that breaks the spec's quoting is split as GLib splits it, and logged.

entry.command is the app's Exec line as a list of arguments, field codes filled in as for a launch with no files. Use it to search by the program's name, or to run a terminal app in a terminal of your choice, in entry.working_dir. It is empty without an Exec or for one that can't be split. 

// "firefox" for /usr/lib/firefox/firefox %u
let program = entry.command.first().and_then(|path| std::path::Path::new(path).file_name());

// A terminal app in ghostty.
let mut run = vec![String::from("ghostty"), String::from("-e")];
run.extend(entry.command.iter().cloned());

Files

cx.file_view(path) follows a text file.

let note = cx.file_view("/home/me/notes/today.txt");
let text = note.text();
Text::new(move || text.get().unwrap_or_default().trim().to_owned())
Method What it gives or does
text() A signal holding Option<String>: the file's text, read again whenever it changes on disk, and 50 ms after a write to a file still open, such as a log. None while it is missing or can't be read.
error() A signal holding why the last read failed, as a FileError with a kind of NotFound, PermissionDenied, NotAFile or Other.
write(text) Replaces the file's text by writing a new file and renaming it over the old one.

Files up to 16 MiB are read, and changes come through inotify. Files under /proc and many under /sys change without telling inotify, so read those yourself on an interval, and only while the value shows. 

let load = cx.signal(String::new());
let read = move || load.set(std::fs::read_to_string("/proc/loadavg").unwrap_or_default());
read();
cx.interval(Duration::from_secs(5), read);

Folders

cx.folder_view(path) lists one level of a folder, sorted by name, and follows it as files come and go, as a wallpaper picker needs. 

let folder = cx.folder_view("/home/me/Pictures/Wallpapers");
let pictures = cx.memo(move || {
  folder.entries().get().into_iter()
    .filter(|e| e.name.ends_with(".jpg") || e.name.ends_with(".png"))
    .collect::<Vec<_>>()
});

Each FolderEntry has path, name, is_dir, size and modified. Hidden files are included, at most 10,000 entries are kept, and a change is read 50 ms later.

Fetch from the web

cx.http_get(url) fetches through the system's curl, so the shell never waits on the network. 

let weather = cx.http_get("https://wttr.in/?format=%t");
cx.interval(Duration::from_secs(600), move || weather.refresh());
Text::new(move || weather.body().get().unwrap_or_default())

body() keeps the last good reply, error() says why the last fetch failed, and loading() is true while one runs. A reply is at most 4 MiB and 30 s unless max_size and timeout say otherwise. Parse JSON with crabshell::serde_json.

cx.cover_art(url) turns a player's art_url into a file for an Image, downloading an https: one into ~/.cache/crabshell/art. 

let art = cx.cover_art(move || playing.get().map(|p| p.art_url).unwrap_or_default());

The clipboard

let clipboard = cx.clipboard();
let history = clipboard.history();
Text::new(move || clipboard.text().get().unwrap_or_default())

text() follows every copy, whatever window has the keyboard, and set_text(text) copies. history() keeps copies from its first call, newest first: text, or an image as a file an Image can show, at most 100 entries. copy(id) puts one back, remove(id) and clear_history() forget. A password manager's copy is never shown or kept.

Selecting text in a field or a selectable Text sets the primary selection, and a middle click in a field pastes it.

Settings in a JSON file

cx.json_file(path, default) is a Signal<T> kept in step with a JSON file, both ways. Setting the signal rewrites the file, and editing the file updates the signal. 

#[derive(Clone, PartialEq, serde::Serialize, serde::Deserialize)]
struct Settings {
  bar_height: u32,
  show_seconds: bool,
}

let settings = cx.json_file(
  "/home/me/.config/my-shell/settings.json",
  Settings { bar_height: 30, show_seconds: false },
);

PanelWindow::new(output).height(move || settings.get().bar_height)

The signal holds default until the file is read. A missing file and its directory are made at the first set. A file that isn't valid JSON for the type is logged and left alone.

The type needs serde's Serialize and Deserialize, so add serde = { version = "1", features = ["derive"] } to your Cargo.toml. Plain types such as bool, String and Vec<String> need no derive.

State that survives a reload

cx.persist(key, default) is a signal whose value survives crabshell run swapping the shell after an edit. 

let count = cx.persist("clicks", 0_u32);
let open = cx.persist(&format!("drawer open on {}", output.name()), false);

Asking again with the same key gives the same signal, which lives as long as the shell does. If an edit changed the value's type so the saved one no longer fits, the default is used and that is logged once. The type needs Serialize and Deserialize.

After cx.signal cx.persist cx.json_file
A reload after an edit Lost Kept Kept
A crash, or a restart of the shell Lost Lost Kept
A reboot Lost Lost Kept, unless the file is under $XDG_RUNTIME_DIR

Call your shell from the command line

cx.ipc(target, function, handler) registers a function that crabshell ipc can call from a key binding, a script or another program. 

let open = cx.signal(false);
cx.ipc("launcher", "toggle", move |_args| {
  open.update(|open| *open = !*open);
  Ok(String::new())
});
cx.ipc("wallpaper", "set", move |args| {
  let path = args.first().ok_or("give a path")?;
  wallpaper.set(Some(path.into()));
  Ok(format!("showing {path}"))
});
$ crabshell ipc launcher toggle
$ crabshell ipc wallpaper set ~/Pictures/lake.jpg
showing /home/me/Pictures/lake.jpg
$ crabshell ipc

The handler gets the arguments as &[String] and returns Result<String, String>. An Ok text is printed, and an Err text is an error with exit status 1. crabshell ipc with no arguments lists every target and function.

  • Names are 1 to 64 ASCII letters, digits, _, - and ..
  • Registering the same target and function again replaces the older handler.
  • A handler lasts as long as the context it was registered on.
  • It runs on the shell's one thread. Start long work with cx.process and return.

Bind a key in your compositor to a call.

# Sway
bindsym $mod+d exec crabshell ipc launcher toggle

# Hyprland
bind = SUPER, D, exec, crabshell ipc launcher toggle

The shell names its socket after WAYLAND_DISPLAY, so crabshell ipc reaches the shell of the session it is run in.

Unix sockets

cx.socket(path) connects to a Unix socket, for a daemon that speaks a line protocol. 

let state = cx.signal(String::new());
let socket = cx.socket("/run/user/1000/my-daemon.sock").on_line(move |line| state.set(line.to_owned()));
socket.write("status\n");

It has connected(), a signal, plus on_line, on_split, write, reconnect() and close(). It closes when its context goes.

cx.socket_server(path) listens instead. Each client reaches on_connection as a Socket, with a context of its own. A server removes its socket file when it stops. 

cx.socket_server("/run/user/1000/my-shell.sock").on_connection(move |_cx, client| {
  client.write(format!("volume {}\n", volume.get_untracked()));
  client.close();
});

Colors from a picture

cx.quantize_colors(path, depth) finds an image's main colors, most common first. It gives up to 2 to the power of depth colors, so a depth of 3 gives up to eight. 

let colors = cx.quantize_colors(move || wallpaper.get(), 3);
let accent = cx.memo(move || colors.with(|all| all.first().copied()).unwrap_or(ACCENT));

Row::new().style(move || Style::new().background(accent.get()))

The work runs on a thread of its own. The signal starts empty, fills when the colors are found, and follows a changed path.

Ending the shell

cx.exit(code) stops the programs the config started, removes the IPC socket and exits with that status. Under crabshell run, 0 ends the supervisor too, and any status except 0 and 2 starts the shell again.

The icon theme

cx.set_icon_theme("Adwaita") makes icon names resolve in that theme. Call it in the root closure. Without it, the shell uses the theme GTK apps use, gtk-icon-theme-name in ~/.config/gtk-3.0/settings.ini or gtk-4.0/settings.ini, and hicolor when neither names one.

Icon::new("spotify-client").fallback("audio-x-generic") draws the fallback when the first icon isn't in the theme. cx.icon_path(name, size) gives the file a name resolves to, or None when the theme lacks it.
