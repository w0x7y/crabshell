crabshell Docs

Lock screen and logins

A lock screen, a login greeter and a polkit dialog all ask for a password, and Crabshell can be all three. Read the warnings here before you rely on a lock screen you wrote.

Lock screen

The session lock tells the compositor to hide everything but your surfaces, and PAM checks the password.

The session lock

let locked = cx.signal(false);
cx.session_lock(
  SessionLock::new()
    .locked(move || locked.get())
    .style(SCREEN)
    .surface(move |cx, output| lock_surface(cx, output)),
);
Method What it does
locked(bool) Locks the session while true. Turning it false is the only way to unlock.
surface(builder) Builds the widget that covers one monitor. It runs for every monitor, including one plugged in while locked.
style(style) The surfaces' background, and the color and font their text inherits.
on_key(handler) Keys a surface's field or button didn't use, as a panel's on_key gets them.

cx.session_lock returns a ReadSignal<bool> that is true while the compositor says the session is locked. If the compositor refuses, as when another program holds the lock, that is logged and the signal stays false. It needs ext-session-lock-v1.

The lock surfaces get the keyboard, so a TextInput with focus(true) is ready to type in. Escape clearing the password is the usual on_key. 

SessionLock::new().on_key(move |_, key| {
  if key.key == Key::Escape {
    entry.set(String::new());
    true
  } else {
    false
  }
})

Stay locked through a crash

A lock screen that dies leaves the session locked. The compositor keeps the screen covered until a program unlocks it, so your shell must remember it was locked when it comes back.

A plain signal forgets on every restart, and cx.persist survives a reload but not a crash. Keep locked in a JSON file under $XDG_RUNTIME_DIR. It survives both, and a reboot clears it. 

let locked = match std::env::var_os("XDG_RUNTIME_DIR") {
  Some(dir) => cx.json_file(PathBuf::from(dir).join("crabshell/lock.json"), false),
  None => cx.signal(false),
};
cx.ipc("lock", "on", move |_| {
  locked.set(true);
  Ok(String::new())
});

Then crabshell ipc lock on locks, from a key binding or an idle daemon. To lock after five minutes away, use cx.idle_monitor.

Try a lock screen in a nested compositor before you trust it with your session. If it can't unlock, you need another virtual terminal to recover.

PAM

cx.pam(service) checks a password through PAM. The service is the name of a file in /etc/pam.d, such as login. start(None) checks the shell's own user, found through NSS, so users from LDAP or systemd-homed work. 

let pam = cx.pam("login");
let state = pam.state();
Method What it gives or does
start(user) Starts an attempt for a user by name, or with None for the user the shell runs as.
respond(text) Answers the question PAM asked.
abort() Stops the attempt. PAM has no cancel, so a module that is still busy, such as a fingerprint reader, finishes first, and a start meanwhile shows Busy until it has.
state() A signal holding a PamState.
messages() A signal holding the lines PAM sent during the attempt, each a PamMessage::Info or PamMessage::Error.
PamState What it means
Idle Nothing is running.
Asking { message, visible } PAM asked a question and waits for respond. visible is false for a password.
Busy PAM is working.
Done(result) The attempt ended with PamResult::Success, Failure, or Error { kind, message }.

Failure means the password was wrong. Error means PAM couldn't check at all.

Take the password first

An attempt that ends while PAM waits for an answer counts as a failed login, and with pam_faillock enough of those lock the account. So don't start PAM when the lock screen appears.

Take the password into a signal, start PAM when the user presses Enter, and answer the moment PAM asks. 

let entry = cx.signal(String::new());
let waiting = cx.signal(false);   // Enter was pressed before PAM asked
let notice = cx.signal(String::new());
{
  let pam = pam.clone();
  cx.effect(move || match state.get() {
    PamState::Asking { .. } if waiting.get_untracked() => {
      waiting.set(false);
      pam.respond(entry.get_untracked());
      entry.set(String::new());
    }
    PamState::Done(result) => {
      waiting.set(false);
      entry.set(String::new());
      match result {
        PamResult::Success => {
          notice.set(String::new());
          locked.set(false);
        }
        PamResult::Failure => notice.set(String::from("Wrong password")),
        PamResult::Error { message, .. } => notice.set(message),
      }
    }
    _ => {}
  });
}
let accept = move |_: &Cx, text: &str| match state.get_untracked() {
  PamState::Asking { .. } => {
    pam.respond(text);
    entry.set(String::new());
  }
  PamState::Busy => {}
  _ => {
    waiting.set(true);
    pam.start(None);
  }
};

The surface builder runs once per monitor, so the handler is shared through an Rc. 

let accept = std::rc::Rc::new(accept);
cx.session_lock(
  SessionLock::new()
    .locked(move || locked.get())
    .style(SCREEN)
    .surface(move |_, _| {
      let accept = std::rc::Rc::clone(&accept);
      Column::new()
        .gap(12)
        .align(Align::Center)
        .justify(Justify::Center)
        .child(Text::new("Locked"))
        .child(
          TextInput::new(entry)
            .password(true)
            .placeholder("password")
            .focus(true)
            .on_accept(move |cx, text| accept(cx, text))
            .style(FIELD),
        )
        .child(Text::new(move || notice.get()).style(NOTICE))
    }),
);

Every monitor's field shares one entry signal, so any of them can submit it. To freeze the field while PAM checks the password, add .read_only(move || state.get() == PamState::Busy). A read-only field takes no typing, and its keys go on to on_key. The answer is never logged. The lock example is the full file.

Greeter

A greeter is the login screen greetd shows before any session exists. greetd starts your shell inside a small compositor, with GREETD_SOCK set, from a line in /etc/greetd/config.toml. 

[default_session]
command = "cage -s -- /usr/local/bin/greeter"

cx.greetd() talks to it.

Method What it gives or does
create_session(user) Starts a login for a user.
respond(answer) Answers the question greetd asked, such as the password.
start_session(command, env) Starts the authenticated session with a command such as ["sway"], and extra environment lines such as XDG_SESSION_TYPE=wayland.
cancel() Ends the login being made.
state() A signal holding a GreetState.
messages() A signal holding the informative and error lines greetd sent.

GreetState is Idle, Busy, Asking { message, visible }, Authenticated, Started or Failed { message, auth }. auth is true when the credentials were refused, which the user can try again.

One effect drives the flow.

let greetd = cx.greetd();
let state = greetd.state();
let user = cx.signal(String::new());
let notice = cx.signal(String::new());
{
  let (greetd, shell) = (greetd.clone(), cx.clone());
  cx.effect(move || match state.get() {
    GreetState::Authenticated => {
      greetd.start_session(vec!["sway".to_string()], Vec::new());
    }
    // The session starts once the greeter is gone.
    GreetState::Started => shell.exit(0),
    GreetState::Failed { message, auth } => {
      notice.set(message);
      // A refused password asks again for the same user.
      if auth {
        greetd.create_session(&user.get_untracked());
      }
    }
    _ => {}
  });
}

The field's on_accept sends the user name while the state is Idle or Failed, and the answer while it is Asking. Its password follows visible. 

TextInput::new(entry)
  .password(move || matches!(state.get(), GreetState::Asking { visible: false, .. }))
  .focus(true)
  .on_accept(accept)

greetd joins the session command with spaces and runs it through sh, so quote an entry that has spaces. A greeter is a normal binary. Build it with cargo and install it where greetd's config points. The greeter example is complete.

Polkit agent

cx.polkit_agent() makes the shell the session's polkit agent, the program that asks for the password when another program needs administrator rights. 

let agent = cx.polkit_agent();
let request = agent.request();

request() is a ReadSignal<Option<AuthRequest>>, the request being answered now. One shows at a time, and up to 8 more wait.

AuthRequest field What it holds
action_id The action polkit is asked about, such as org.freedesktop.systemd1.manage-units.
message The sentence to show the user.
icon_name A themed icon for the action, or empty.
identities The users who may answer, by name. The first is the one asked now.
state An AuthState: Waiting, Asking { message, visible }, Busy or Failed { message }.
info, errors Lines PAM sent during this try, such as "touch your security key".
Method What it does
respond(text) Answers the question. After a failure, it starts another try. After the third failure the request goes.
cancel() Gives up on the request.
pick_identity(name) Asks another of the request's users instead.

Build the dialog in a child context made when request turns Some and disposed when it turns None, with a panel on the overlay layer and KeyboardFocus::Exclusive. 

let entry = cx.signal(String::new());
let prompt = move || match request.get().map(|r| r.state) {
  Some(AuthState::Asking { message, .. }) => message,
  Some(AuthState::Failed { message }) => message,
  Some(AuthState::Busy) => String::from("Checking…"),
  _ => String::new(),
};

Column::new()
  .gap(10)
  .child(Text::new(move || request.get().map(|r| r.message).unwrap_or_default()).max_lines(3))
  .child(Text::new(prompt))
  .child(
    TextInput::new(entry)
      .password(true)
      .focus(true)
      .on_accept(move |cx, text| {
        cx.polkit_agent().respond(text);
        entry.set(String::new());
      }),
  )
  .child(Button::new(Text::new("Cancel")).on_click(|cx| cx.polkit_agent().cancel()))

Only one agent can serve a session. If another is running, polkit refuses the registration, the shell logs it, and no requests arrive.

Identities are looked up through NSS on a thread of their own, so users from LDAP or systemd-homed are offered and a slow lookup never holds up the shell. The agent talks to polkit's helper socket, or without one runs polkit-agent-helper-1 from /usr/lib/polkit-1, /usr/libexec or NixOS's /run/wrappers/bin.
