crabshell Docs

Compositors and windows

Workspaces come four ways: Sway's IPC, Hyprland's IPC, niri's IPC and the ext-workspace-v1 protocol. Windows and screen pictures come through protocols most wlroots compositors share.

Which one to use

Your compositor Workspaces from Other windows from
Sway, or i3-compatible IPC cx.sway() cx.toplevels()
Hyprland cx.hyprland() cx.hyprland().toplevels() or cx.toplevels()
niri cx.niri() cx.niri().windows() or cx.toplevels()
labwc and others with ext-workspace-v1 cx.window_manager() cx.toplevels()

Each stays empty and asleep where its compositor isn't running, so one config can serve two compositors.

Sway

let workspaces = cx.sway().workspaces();
let output_name = output.name();

Row::new().gap(4).children_keyed(
  move || {
    workspaces.get().into_iter().filter(|w| w.output == output_name).collect::<Vec<_>>()
  },
  |w| w.id,
  |_cx, ws| {
    Button::new(Text::new(move || ws.get().name))
      .style(move || if ws.get().focused { WS_FOCUSED } else { WS })
      .on_click(move |cx| cx.sway().focus_workspace(&ws.get().name))
  },
)
Method What it gives or does
workspaces() Vec<Workspace>: each with id, name, output, focused, visible and urgent.
outputs() Vec<SwayOutput>: each with name, focused, active, current_workspace, x, y, width, height and scale.
focus_workspace(name) Switches to a workspace.
dispatch(command) Runs any Sway command, as swaymsg does. It is sent as written, so quote a name that has spaces.
on_event(kinds, handler) Calls handler with each event of the kinds you list.

The service connects to the socket in $SWAYSOCK. If that is unset or the first connection fails, the lists stay empty. A working connection that drops is retried every 2 s.

Sway deletes an empty workspace once it isn't shown. For a fixed set of numbered slots, build them yourself and look each one up in the list.

Raw events

on_event covers what the lists don't, such as the binding mode or the focused window's title. 

let mode = cx.signal(String::from("default"));
cx.sway().on_event(&[SwayEventKind::Mode], move |event| {
  // event.data is Sway's JSON for the event.
  if let Ok(json) = serde_json::from_str::<serde_json::Value>(&event.data) {
    mode.set(json["change"].as_str().unwrap_or("default").to_owned());
  }
});

The kinds are Workspace, Output, Mode, Window, BarconfigUpdate, Binding, Shutdown, Tick, BarStateUpdate and Input. Sway is asked only for the kinds some handler wants. The handler lives as long as the context cx.sway() was called on. This example needs serde_json in the config's own Cargo.toml.

Hyprland

let hyprland = cx.hyprland();
let workspaces = hyprland.workspaces();
let toplevels = hyprland.toplevels();
Method What it gives or does
workspaces() Vec<HyprlandWorkspace>: each with id, name, monitor, windows, focused, active and urgent.
monitors() Vec<HyprlandMonitor>: each with id, name, description, focused, active_workspace, x, y, width, height and scale.
toplevels() Vec<HyprlandToplevel>: each with address, class, title, workspace, monitor, floating, fullscreen, focused and urgent.
focus_workspace(target) Switches to a workspace, named as 2 or name:web.
dispatch(command) Sends a raw dispatch.
on_event(handler) Calls handler with every raw HyprlandEvent, which has a name and its data. event.parse(n) splits the data into at most n fields.

A named workspace has an id of None. Special workspaces have names that start with special:. The hyprland example is a complete bar. 

.on_click(move |_| {
  let ws = ws.get();
  let target = match ws.id {
    Some(id) if id > 0 => id.to_string(),
    _ => format!("name:{}", ws.name),
  };
  hyprland.focus_workspace(&target);
})

**Be careful with dispatch.** When Hyprland's config is Lua, which it can be from 0.55 and always is from 0.57, the command is a Lua expression that runs inside the compositor. Never build one from a window title, a class or a workspace name, since those come from other programs. focus_workspace quotes names for you.

The service finds Hyprland's sockets through $HYPRLAND_INSTANCE_SIGNATURE. Without it the lists stay empty, which is logged once.

niri

let niri = cx.niri();
let workspaces = niri.workspaces();
Row::new().children_keyed(
  move || workspaces.get(),
  |w| w.id,
  move |_cx, ws| {
    let id = ws.get_untracked().id;
    Button::new(Text::new(move || ws.get().idx.to_string()))
      .on_click(move |cx| cx.niri().focus_workspace(id))
  },
)

workspaces(), windows(), keyboard_layouts() and overview_open() follow niri's event stream at $NIRI_SOCKET. focus_workspace(id) and focus_window(id) take niri's ids, action(json) sends any niri action, and on_event(handler) gets every raw event. crabshell::serde_json builds the JSON. 

use crabshell::serde_json::json;
cx.niri().action(json!({ "Spawn": { "command": ["foot"] } }));

Any compositor with ext-workspace

cx.window_manager() reads workspaces through ext-workspace-v1, which labwc supports. It uses the protocol's words. A windowset is a workspace, and a projection is a group of workspaces shown on one or more monitors. 

fn workspaces(cx: &Cx, output: &Output) -> Row {
  let manager = cx.window_manager();
  let name = output.name();
  Row::new().children_keyed(
    move || manager.windowsets_on(&name),
    |set| set.id,
    move |_, set| {
      Button::new(Text::new(move || set.get().name))
        .on_click(move |_| manager.activate(set.get().id))
    },
  )
}
Method What it gives or does
windowsets() Vec<Windowset>: each with id, name, active, urgent, hidden, its projection, and can_activate, can_deactivate, can_remove and can_assign.
projections() Vec<WindowsetProjection>: each with id, the outputs it shows on, and can_create.
windowsets_on(output) The workspaces a bar on that monitor should list.
activate(id), deactivate(id), remove(id) Requests about one workspace. The can_ fields say which the compositor takes.
assign(id, projection), create_windowset(projection, name) Moves a workspace to another group, or makes one.

WindowManager is a Copy handle. Without the protocol the lists stay empty, and that is logged.

Other programs' windows

cx.toplevels() lists every window on the desktop, for a taskbar, a window switcher or an overview. It uses wlr-foreign-toplevel-management. 

let toplevels = cx.toplevels();
let list = toplevels.list();

Row::new().children_keyed(
  move || list.get(),
  |toplevel: &Toplevel| toplevel.id,
  move |_cx, toplevel| {
    Button::new(Text::new(move || toplevel.get().title).ellipsis(true))
      .style(move || if toplevel.get().activated { TASK_ON } else { TASK })
      .on_click(move |_| toplevels.activate(toplevel.get().id))
      .on_middle_click(move |_| toplevels.close(toplevel.get().id))
  },
)

A Toplevel has id, title, app_id, the outputs it is on, activated, maximized, minimized, fullscreen and its parent. The methods take an id: activate, close, set_maximized(id, bool), set_minimized(id, bool) and set_fullscreen(id, bool).

For a window's icon, look its app_id up in the desktop entries. 

let icon = cx.desktop_entries().lookup(&toplevel.app_id).map(|entry| entry.icon);

Live pictures of windows and monitors

ScreencopyView shows what a monitor or a window shows, captured by the compositor. Its style gives it a size. 

ScreencopyView::new(CaptureSource::Toplevel(id))
  .live(true)
  .style(Style::new().width(192.0).height(108.0).radius(4.0))
Method What it does
ScreencopyView::new(source) CaptureSource::Output(name) for a monitor or CaptureSource::Toplevel(id) for a window, with an id from cx.toplevels().
live(bool) Off, the default, shows one frame. On, each change to the source brings a new frame.
paint_cursors(bool) Whether the pointer is drawn into the picture. Off by default.
fit(fit) How the picture fills the box, as on an Image.
crop(rect) Shows one part of the picture, a Some(Rect) in the source's logical pixels. None, the default, shows it whole.
shown(signal) Writes true to a Signal<bool> once the view's picture is on screen.

A live view of a window that doesn't change wakes nothing. The view draws nothing until its first frame, and keeps the last frame when its source goes. It needs ext-image-copy-capture-v1.

One picture, many views

cx.capture(source) takes one picture of a monitor or a window. Any number of ScreencopyView::of(capture) views show it, each whole or cropped, and it is taken only once. capture.refresh() takes a new picture, and capture.ready() turns true when it has landed. Until then the views keep the old one. 

let screen = cx.capture(CaptureSource::Output(String::from("DP-1")));
let whole = ScreencopyView::of(screen).style(Style::new().width(1920.0).height(1080.0));
let corner = ScreencopyView::of(screen)
  .crop(Some(Rect::new(0.0, 0.0, 480.0, 270.0)))
  .style(Style::new().width(480.0).height(270.0));

A crop is in the monitor's logical pixels, the same coordinates Sway gives for window rectangles, so a view can show one window cut out of the monitor's picture. A capture of a monitor includes the shell's own windows on it, so hide your view of it before you refresh. A 1080p picture takes about 8 MB until the capture's context goes, so make a capture for a passing effect in a child context and dispose it after.

shown tells you when the view's current picture is on screen, after the compositor presented the frame that drew it. Wait for it before you change what's underneath, so the change never flashes. Give each view a signal of its own.

Global shortcuts

A shell window gets keys only while it has the keyboard. For a key that works anywhere, bind it in the compositor's config to a crabshell ipc call. 

# Sway
bindsym $mod+d exec crabshell ipc launcher toggle

On Hyprland, cx.global_shortcut(app_id, name, description) registers a shortcut the compositor binds directly. It returns a ReadSignal<bool> that is true while the key is held, which also makes push-to-talk possible. 

let held = cx.global_shortcut("crabshell", "launcher", "Show the launcher");
cx.effect(move || {
  if held.get() {
    open.update(|open| *open = !*open);
  }
});
# hyprland.conf
bind = SUPER, D, global, crabshell:launcher

Pick an app id of your own, since Hyprland drops a program that registers a pair another one holds.

What each feature needs

Crabshell asks for a protocol only when a config uses the feature. A compositor without it gets one log line and an empty result.

Feature Protocol
PanelWindow wlr-layer-shell. Required.
PopupWindow, FloatingWindow xdg-shell
Sharp drawing at 1.25, 1.5 and 1.75 scale wp-fractional-scale-v1 with wp-viewporter. Without them windows draw at the next whole scale.
Cursor shapes wp-cursor-shape-v1
Input methods in text fields zwp-text-input-v3
blur ext-background-effect-v1
cx.idle_monitor, inhibit_idle ext-idle-notify-v1, idle-inhibit-unstable-v1
cx.toplevels() wlr-foreign-toplevel-management
ScreencopyView ext-image-copy-capture-v1, with ext-foreign-toplevel-list-v1 for windows
cx.session_lock ext-session-lock-v1
cx.window_manager() ext-workspace-v1
inhibit_shortcuts keyboard-shortcuts-inhibit-unstable-v1
cx.global_shortcut hyprland-global-shortcuts-v1
focus_grab hyprland-focus-grab-v1
compositor_opacity, visible_mask hyprland-surface-v1, from Hyprland 0.47
