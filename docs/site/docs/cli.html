crabshell Docs

The crabshell command

crabshell creates a config, builds it, runs it, swaps it when you save and restarts it when it crashes.

Commands

Command What it does
crabshell init Writes the template config to ~/.config/crabshell. It refuses if the directory exists.
crabshell init --path DIR The same, but the config builds against the Crabshell clone at DIR instead of crates.io.
crabshell run Builds the config, starts the shell, rebuilds on every save and restarts the shell if it crashes.
crabshell check Runs cargo check on the config and prints the errors.
crabshell ipc Lists the functions the running shell offers.
crabshell ipc TARGET FUNCTION [ARGS...] Calls one and prints what it returns.
crabshell help Shows the usage.
Exit status Meaning
0 It worked. For run, the shell ended on purpose or the session is gone.
1 The command failed, and says why. For ipc, the handler returned an error or no shell is running. For check, cargo's own status is passed on.
2 The command line was wrong. The usage is printed.

What run does

  1. It watches Cargo.toml and everything under src/.
  2. It runs cargo build in the config directory, with the output in ~/.cache/crabshell/target.
  3. It starts the built program, which reports ready once every panel has drawn a frame.
  4. It sleeps, using about 5 MiB. It wakes once, a minute in, to keep that build as the last one that worked.

On a save

  1. Once 300 ms pass with no further change, it runs cargo build. Hidden files, editor backups and swap files don't count.
  2. If the build fails, the running shell stays up. The compiler's output prints in the terminal, and the first error is sent as a desktop notification.
  3. If it succeeds, the shell writes every cx.persist value to a file and exits.
  4. The new shell starts, reads the saved values and draws.

For a one-line edit to the template bar, the build takes 0.7 s and the screen is without a bar for 13 to 19 ms. A build that produces the same program as before doesn't reload.

On a crash

If the shell exits with any status but 0 or 2, or dies from a signal, crabshell run starts it again after 1 s. Each further crash doubles the wait, up to 30 s.

Three crashes within a minute of a new build make it give up on that build, start the last build that worked and send a notification. That build is the newest one that ran a full minute without crashing. Your next save builds again.

If the very first build fails, run starts the last build that worked if there is one, and exits with 1 otherwise.

Stopping

Ctrl-C or SIGTERM stops the shell and then crabshell run. The shell stops every program it started with cx.process and removes its IPC socket.

When the compositor exits, the shell exits with status 2. crabshell run takes that as the session ending and stops with status 0.

Logs

Everything goes to standard error. Lines from crabshell run itself start with crabshell:, and the shell's lines pass straight through. CRABSHELL_LOG sets how much the shell says. 

$ CRABSHELL_LOG=debug crabshell run

The levels are error, warn, info, debug, trace and off, and the default is info. At info the shell logs its time to the first frame, each panic with its place in the tree, each service that found nothing to connect to, and each protocol the compositor lacks.

Started from your compositor's config, the output goes wherever the compositor's does. To keep it, send it to a file. 

# Sway
exec ~/.cargo/bin/crabshell run 2>> ~/.cache/crabshell/log

Files and directories

Path What it is
~/.config/crabshell/ Your config: Cargo.toml and src/. Follows XDG_CONFIG_HOME.
~/.cache/crabshell/target/ Cargo's build output. Safe to delete. Follows XDG_CACHE_HOME.
~/.cache/crabshell/last-good A copy of the newest build that ran for a minute without crashing.
$XDG_RUNTIME_DIR/crabshell/state.json The cx.persist values, written for a reload and removed when the new shell has read them.
$XDG_RUNTIME_DIR/crabshell/control-<pid>.sock How crabshell run and its shell talk. Removed when run ends.
$XDG_RUNTIME_DIR/crabshell/ipc-<display>.sock Where the shell answers crabshell ipc, named after WAYLAND_DISPLAY. It exists once a config registers a handler.

The directory under $XDG_RUNTIME_DIR is readable only by you. crabshell run refuses to start without XDG_RUNTIME_DIR.

Environment variables

Variable What it does
CRABSHELL_LOG The shell's log level.
CARGO The cargo that run and check call, when it isn't the one on PATH.
XDG_CONFIG_HOME, XDG_CACHE_HOME Where the config and the build output live.
WAYLAND_DISPLAY The compositor the shell connects to, and the name of its IPC socket.
SWAYSOCK, HYPRLAND_INSTANCE_SIGNATURE How the Sway and Hyprland services find their compositor.
GREETD_SOCK How cx.greetd() finds greetd.

Running the shell without the command

The shell is an ordinary program, so cargo run in the config directory starts it, and so does the built binary. It then has no reload and no restart on a crash. A greeter runs this way.

crabshell::run exits with status 1 if the root closure panics, and with 2 if there is no compositor, it lacks layer-shell, or the connection is lost.

The template's Cargo.toml

[package]
name = "my-shell"
version = "0.1.0"
edition = "2024"

[dependencies]
crabshell = "0.5"

[profile.dev]
opt-level = 1

[profile.dev.package."*"]
opt-level = 3

crabshell run builds with cargo's dev profile. The two profile sections compile every dependency with full optimization, once, and your own crate lightly, so an edit rebuilds in under a second. Keep them.

The package name is yours, and so is anything under [dependencies]. The config must build exactly one program.
