writing a config

a config is a normal cargo project whose main calls crabshell::run. this page goes through the template crabshell init writes, then the rules the api keeps.

the template

Cargo.toml

[package]
name = "my-shell"
version = "0.1.0"
edition = "2024"

[dependencies]
crabshell = "0.1"

[profile.dev]
opt-level = 1

[profile.dev.package."*"]
opt-level = 3

the dependencies build once with full optimization, and your own crate at level 1, so an edit rebuilds fast and the bar still runs fast.

src/main.rs

use crabshell::prelude::*;

const BAR: Style = Style::new()
    .background(Color::rgb(0x1e, 0x1e, 0x2e))
    .color(Color::rgb(0xcd, 0xd6, 0xf4))
    .font(Font::new("Inter", 13.0));
const WS: Style = Style::new().padding(2, 8).radius(4.0);
const WS_FOCUSED: Style = WS.background(Color::rgb(0x45, 0x47, 0x5a));

fn main() {
    crabshell::run(|cx| cx.per_output(bar));
}

fn bar(cx: &Cx, output: &Output) -> PanelWindow {
    let clock = cx.clock(Precision::Minute);
    let workspaces = cx.sway().workspaces();
    let sink = cx.audio().default_sink();
    let output_name = output.name();

    PanelWindow::new(output)
        .anchors(Edge::Top | Edge::Left | Edge::Right)
        .height(30)
        .exclusive_zone(30)
        .style(BAR)
        .child(
            Row::new()
                .gap(8)
                .padding(4, 8)
                .child(Row::new().gap(4).children_keyed(
                    move || {
                        workspaces.get().into_iter()
                            .filter(|w| w.output == output_name)
                            .collect::<Vec<_>>()
                    },
                    |w| w.id,
                    |_cx, ws| {
                        Button::new(Text::new(move || ws.get().name))
                            .style(move || if ws.get().focused { WS_FOCUSED } else { WS })
                            .on_click(move |cx| cx.sway().focus_workspace(&ws.get().name))
                    },
                ))
                .child(Spacer::new())
                .child(Tray::new().icon_size(18))
                .child(
                    Button::new(Text::new(move || match sink.get() {
                        Some(s) if s.muted => "muted".to_string(),
                        Some(s) => format!("vol {}%", s.volume_percent),
                        None => "no audio".to_string(),
                    }))
                    .on_click(|cx| cx.audio().toggle_mute())
                    .on_scroll(|cx, steps| cx.audio().change_volume(steps * 5)),
                )
                .child(Text::new(move || clock.get().strftime("%a %d %b  %H:%M").to_string())),
        )
}

a bar per monitor

  • crabshell::run(|cx| ...) takes the root closure, starts the event loop and never returns.
  • cx.per_output(f) calls f for every monitor there is now and every one that appears later. f returns a PanelWindow, or a Vec of them for several windows or none. when a monitor goes, its window and everything f made go with it.
  • PanelWindow::new(output) is a layer-shell window. it takes .anchors(...), .width(...), .height(...), .exclusive_zone(...), .layer(Layer::Top), .style(...) and .child(...).

a value or a closure

every property takes either one. .height(30) sets it once. .height(move || ...) is a binding: it runs again whenever a signal it read changes, and only that property updates. 

Text::new("plain text")
Text::new(move || format!("{} windows", count.get()))

signals

  • Signal<T> can be read and written. ReadSignal<T> is what services hand out. both are Copy, so a move closure takes them without a clone.
  • get() returns a clone and subscribes the closure it runs in. with(|v| ...) reads by reference. set(...) and update(|v| ...) write.
  • cx.signal(value) makes one, cx.memo(|| ...) caches a value worked out from others, and cx.effect(|| ...) runs code whenever what it read changes. 
let count = cx.signal(0);
Button::new(Text::new(move || format!("clicked {}", count.get())))
    .on_click(move |_cx| count.update(|n| *n += 1))

widgets

widget what it does
Row, Column lay children out left to right, or top to bottom, with gap, padding, align and justify
Stack draws its children on top of each other
Text text from a value or a closure, with ellipsis and max_lines
Icon an icon from the icon theme, or from pixels, at a size
Button wraps a child and takes clicks, presses, scrolling and keys, with hover_style, pressed_style and focus_style
Image a png, jpeg, gif, webp or svg file at a width and height, with a fit
ScrollView shows part of a taller child and scrolls it with the wheel, its offset in a signal
ListView a scrolling list of rows of one height that builds only the rows in view, with a current row kept in view
TextInput a one-line text field editing a signal, with a placeholder, password dots, the clipboard, input methods and on_accept
Spacer takes the space left in a row or column
Tray the system tray, with icon_size and menu_style
PopupWindow a popup next to the widget that opened it, from cx.open_popup(|cx| ...)
Menu a list of MenuEntry items for a popup, with on_activate
FloatingWindow an ordinary window with a title, size limits, maximized, fullscreen and visible, shown with cx.floating(...)

lists

children_keyed(items, key, view) builds one child per item and keeps it while its key stays in the list. view gets a memo that updates when that item changes, so a workspace that gains focus restyles its own button and nothing else.

events

on_click, on_right_click, on_middle_click and on_press get &Cx. on_scroll also gets the steps, up positive. all of them run on the main thread.

a window with a keyboard_focus gets keys. they go to the focused text field, then the focused button's on_key, then the window's; a handler returns true when it used the key. after that, tab moves the focus and enter or space clicks the focused button. the launcher example puts it together.

styles

a Style is Copy, and every method on it is a const fn, so a theme is a set of constants. the methods are background, gradient, shadow, color, font, padding, radius, border, opacity, clip, width, height, transition and merge. colors come from Color::rgb, Color::rgba or Color::hex. 

const PILL: Style = Style::new().padding(2, 8).radius(4.0);
const PILL_ON: Style = PILL.background(Color::hex("#3a404b"));

Text takes its color and font from the nearest parent that sets them. nothing else is inherited.

animation and effects

a style with a transition fades in when it takes over, as when a hover style does: its background, gradient, shadow, color, border, radius and opacity move over that time. cx.animate makes any number or color slide to each new target. nothing ticks while nothing moves, so an idle bar still sleeps. 

const TAB: Style = Style::new().radius(6.0).transition(Transition::new(150));
const CARD: Style = Style::new()
    .gradient(Gradient::linear(90.0, Color::hex("#1e1e2e"), Color::hex("#313244")))
    .shadow(Shadow::new(0.0, 2.0, 8.0, Color::rgba(0, 0, 0, 160)));

let offset = cx.animate(move || picked.get() as f32 * 44.0, Transition::new(250));

PanelWindow::blur(Some(region)) asks the compositor to blur what is behind that part of the window, through ext-background-effect-v1. a compositor without it, like sway, shows the window unblurred and the log says so once. examples/effects.rs puts it all together.

services

call gives you
cx.clock(Precision::Minute) the time, as a ReadSignal of jiff::Zoned that changes on the minute. Precision::Second ticks every second
cx.sway().workspaces() sway's workspaces, each with its name, output and focused. focus_workspace(name) switches
cx.audio().default_sink() the default output's volume and mute. toggle_mute() and change_volume(percent) change them
cx.tray() the tray's items and their menus. the Tray widget uses it for you
cx.audio().sinks() every output, and sources() and streams() for inputs and apps playing, each with its volume and mute, and setters for them
cx.upower().display_device() the battery: percent, charging or not, time left. cx.power_profiles() reads and sets the profile
cx.network() devices and wi-fi networks from networkmanager, with connect, scan and wi-fi on or off
cx.bluetooth() adapters and devices from bluez, with their battery, and connect, pair and power
cx.mpris().players() media players and their tracks, with play_pause, next and seek. position_at(now) says where playback is
cx.notifications() the shell becomes the notification server: popups() for toasts, list() for the history, dismiss and invoke
cx.idle_monitor(timeout) true once you've been away for timeout. a window's inhibit_idle keeps the screen awake
cx.desktop_entries() your installed apps, with launch and lookup(app_id) to find a window's icon
cx.process(|| ["uptime", "-p"]) runs a program: stdout(), on_line, exit_status(), and it runs again when a signal the command read changes. cx.exec_detached starts one that runs on its own
cx.file_view(path) a file's text(), followed as it changes. cx.json_file(path, default) keeps a Signal and a json file in step both ways, and cx.socket(path) talks to a unix socket
cx.ipc(target, function, handler) a function crabshell ipc target function args calls from the command line
cx.toplevels() every program's windows, with activate, close and the rest
cx.quantize_colors(path, depth) an image's main colors, as for a theme from a wallpaper

a service starts the first time you ask for it, so one you don't use costs nothing. one that can't run, like sway with no socket, gives None or an empty list and logs once.

keep state across reloads

cx.persist(key, default) gives a Signal whose value survives a reload, for any type that serde can save. if an edit changes the type so the saved value no longer fits, it starts from the default and logs once. 

let clicks = cx.persist(&format!("clicks on {}", output.name()), 0_u32);

when your code panics

  • a panic in a binding, an effect, an event handler or a per_output builder is caught. that part turns off, and the log names it with its widget path. the rest keeps running.
  • a panic in the closure passed to crabshell::run ends the shell with status 1, and crabshell run treats it as a crash.
