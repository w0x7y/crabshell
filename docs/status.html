Cost of the same bar

CrabshellQuickshell 0.3.2

Phase 0, 2026-11-10. The full v0.1 bar, with workspaces, tray, volume and a clock, measures 18.8 MiB (15% of Quickshell's 125.2 MiB) and a 14 ms first frame on headless Sway. Quickshell drew on the GPU through OpenGL, its default.

Where Crabshell is ahead

Things the numbers don't show

  • One bad binding stays contained. A panic in a config closure is logged with its widget path, that binding turns off, and the rest of the shell keeps running.
  • Crashes recover on their own. The supervisor restarts a dead shell in about a second, and after three quick crashes it runs the last build that worked.
  • Mistakes show up before the shell runs. The compiler checks every config, and rust-analyzer gives completion and inline errors in your editor.
  • Idle means asleep. A bar with a minute clock wakes once a minute and does nothing in between, and every test suite checks that.
  • A failed edit keeps your bar up. The old shell stays on screen and a desktop notification shows the first compiler error.

Where Crabshell is behind

The price of compiled configs, and the gaps

  • Configs have to compile. Quickshell reloads QML without a build. Here the first build takes minutes and each edit rebuilds: 0.7 s for a one-line change to the template bar.
  • Every user needs a Rust toolchain, and has to learn closures and move to write a config.
  • A reload restarts the shell. The bar is gone for 13 to 19 ms, and every color change is a rebuild.
  • Sway and wlroots only. No Hyprland, niri or i3 yet.
  • No animation, blur or shadows yet, and text uses grayscale antialiasing where Qt uses subpixel.
  • Most of Quickshell isn't built yet: many of its types are still missing, and there are no existing configs to copy.

Two processes, one thread each

How it fits together

Your config compiles into the shell. The supervisor rebuilds and restarts it. Inside the shell, everything runs on one event loop. Select a box to see what it owns.

Decisions still open

  • Which other wlroots compositors to test (river, labwc, Wayfire), and which implement ext-workspace-v1.
  • Start the new shell before stopping the old one on reload, to remove the blink. Both bars would reserve space for a moment.
  • Stay on libpulse after v0.1, or move to native PipeWire.
  • When to add Hyprland and niri, and in which order.
  • Exit with status 1 when every output's builder panics at startup, so the fallback to last-good can fire.
  • Add cargo-deny and a deny.toml; licenses are checked by hand until then.

What the marks mean

  • Green check: built and working in Crabshell.
  • Amber bar: partly built. The note says what's there.
  • Empty box: not built yet. The note gives the phase it's planned for.
  • Red cross: tried, and it failed. Nothing has so far.
  • Gray dash: QML plumbing that plain Rust already covers.
